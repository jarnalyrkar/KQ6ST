King's Quest VI AGI Demake - bugs found in the game data (8/30/2024 release)
=============================================================================

Found while playing the Atari ST version (Marakatti's disk image, in
Petari's hard-disk conversion, which runs your DOS game data unchanged on
Sierra's Atari ST AGI interpreter). The items below are in
the logic resources themselves, so they should also affect the DOS version.
Offsets are byte offsets into the logic's code (after the 2-byte length).


1. GAME-BREAKING: pawn shop trade can lose the item (logic 8 -> logic 234)
-------------------------------------------------------------------------
How to reproduce:
  - In the pawn shop, step up to the counter so the TALK/TRADE/TAKE MINT/EXIT
    menu opens.
  - Press DOWN to move to TRADE (or move the selection with the arrow keys
    in any way that ends with a "down" press), then press Return.
  - Pick the mechanical nightingale (or the flute, brush or tinder box) in
    the inventory.
Result: the item is taken away (drop(9) in logic 234), but instead of the
trade Alexander says "What would you take in exhange for the magic map?" and
the trade never happens. The bird is gone for good.

Cause: in room 8, v100 holds ego's direction (get.dir(0,v100)); the menu uses
it to read the arrow keys, and DOWN is direction 5. The TRADE path goes
to new.room(234) without clearing v100. Logic 234 reads v100 as the
conversation topic, and topic 5 is the magic-map question (m13). So both the
item hand-over (v25) and the map question run.

Fix: clear v100 before the item conversation. In logic 8, at the start of the
item path (the erase(5) just before new.room(234), at 0x05fb in the compiled
logic):
    v100 = 0;
    erase(o5); erase(o6); erase(o7); erase(o8);
    discard.view(6);
    new.room(234);
(Patched this way on the ST and tested: the bird trades for the flute as
expected.)


2. "take mint" outside the pawn shop eats the mint (logic 90)
-------------------------------------------------------------
Logic 90 handles said(33,103) - word group 33 is get/take/grab/pick up... -
as "eat mint". So "take mint" anywhere except the pawn shop counter answers
"Alexander eats the mint..." (or "Alexander does not currently have a mint to
eat."). Probably meant to be only the eat group (194).

4. Suggestion: typed commands instead of the pawn shop menu
-----------------------------------------------------------
On the ST the counter menu felt clunky, so the port now uses typed commands
(this is how the ST version plays now; it might be nice in DOS too):
  At the counter:
    talk / talk owner / talk merchant / talk man -> the TALK branch
    trade ... / give ... / show ... / offer ...  -> the TRADE branch
                                                   (inventory picker)
    take mint / get mint / get candy dish        -> the TAKE MINT branch
  Away from the counter:
    talk / trade / give -> m44 ("...he should step up to the counter.")
The vocabulary already has all the words (talk 25, get/take 33, mint 103,
candy dish 68, trade/exchange 196, give/offer/show 1012, merchant/owner 78,
pawn owner 79). Each command simply jumps to the code of the matching menu
choice, so the conversations, trades and points are unchanged. The current
"talk" handler in logic 8 answers "Alexander is not close enough" anywhere
in the room, even at the counter, because the menu was the only way to talk.
The same idea was requested for the ferryman's cabin (not done yet).


5. Reported on the ST, not checked against DOS
----------------------------------------------
These come from a full playthrough on the ST. They may be in the game data
or may come from the ST interpreter; we have not checked them in DOS:
  - Isle of Wonder, 3rd/4th gnome puzzle: the oyster's sleep animation draws
    over the message box, so the text can't be read. Similar with the flame
    animations when talking to the Lord of the Dead.
  - Cliffs of Logic: pressing Return to close the text box on the
    stairs makes Alexander lose his balance (Space does not).
  - Cliffs of Logic, third puzzle: pressing Return to close "Alex examined the
    strange etchings..." also presses the first button, which can't be
    undone, so the puzzle has to be restarted.
  - Outside the treasure room (Isle of the Crown): nothing hints that the
    door needs "talk"; a small hint in the message would help.

Note: the ST version also had memory crashes (Minotaur, druids, Charon,
Jollo's lamp) and a crash when giving milk to the baby's tears. Those were
limits and bugs of the 1987 ST interpreter, not of the game data; they are
fixed on the ST side and need nothing from you.

Thanks for the game!
